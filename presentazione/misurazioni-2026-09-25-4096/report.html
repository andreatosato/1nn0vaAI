Come leggere questi numeri

  • Input è la somma dei token provider di tutte le chiamate, inclusi cached: non è la lunghezza del solo system prompt.
  • Output include reasoning e output intermedi/tool call: non equivale ai token della risposta visibile. Cached e reasoning non vanno aggiunti ai totali.
  • I prompt sono esportati come testo; le richieste logiche includono messaggi e tool. Non sono catture wire. L’anteprima non include contesto runtime/skill.
  • Secondi = durata end-to-end registrata dal backend. Non è TTFT del provider. Le latenze delle chiamate A2A possono sovrapporsi e non vanno sommate come durata della run.
  • Gli agenti contati sono quelli realmente invocati; Inline/Skills hanno un Router modello, A2A include gli specialisti.
  • N/D significa non disponibile, mai zero. Le tariffe/versioni sono congelate in ogni export.
  • Due ripetizioni descrivono osservazioni, non consentono una classifica robusta, stime p95 o conclusioni causali sulla cache.
  • Una run completed non prova che tutti i tool siano riusciti: verificare errori e risposta prima di scegliere l’architettura meno costosa.
  • Le run failed includono solo il percorso eseguito prima dello stop: meno input o meno agenti non significano maggiore efficienza a parità di esito.
  • Tool falliti conta gli eventi tool.called con status failed, senza duplicare gli eventi HTTP della stessa invocazione.
